# 递归调用顺序与树递归

本讲包含四节：Cascade、Inverse Cascade、Tree Recursion、Counting Partitions。依据本次上传讲稿与学习中的实际回答整理。讲稿未显示的代码均根据讲稿还原；练习代码另行标明。

## 1. 贯穿整讲的执行规则

1. 调用函数时，建立一次独立调用，有自己的参数、局部变量和执行位置。
2. 遇到另一个函数调用，当前调用暂停，等待内层完整结束。
3. 内层返回后，外层从暂停的位置继续，不从函数开头重来。
4. `x = f(...)` 先执行整个 `f(...)`，再把返回值赋给 `x`。返回值不会自动改变外层的参数。
5. `return` 只结束当前调用。没有显式返回值时，函数返回 `None`。
6. `print` 产生屏幕输出；`return` 把值交给调用处。打印的值不等于返回值。
7. `if/else` 分支结束不等于函数结束。分支外、函数内的语句还要执行，除非之前已经 `return`。

递归不一定先到底才做任何事：调用前的语句在向内进入时执行；调用后的语句在内层返回后执行。

## 2. Cascade：递归前后打印

输入为正整数。代码根据讲稿还原：

```python
def cascade(n):
    if n < 10:
        print(n)
    else:
        print(n)
        cascade(n // 10)
        print(n)

cascade(123)
```

输出：

```text
123
12
1
12
123
```

`cascade(123)` 先打印自己的 `123`，等待 `cascade(12)` 完整打印 `12、1、12`，再打印自己的 `123`。内层参数变小，外层保存的 `n` 不变。

等价的短写法：

```python
def cascade(n):
    print(n)
    if n >= 10:
        cascade(n // 10)
        print(n)
```

讲稿转写的 “greater than 10” 应按上下文修正为 `n >= 10`，否则输入 `10` 时与原版不等价。学习时优先选容易看清基本情况的写法。

## 3. Inverse Cascade：用高阶函数安排顺序

代码根据讲稿还原，用普通 `def` 展示：

```python
def f_then_g(f, g, n):
    if n:
        f(n)
        g(n)

def grow(n):
    f_then_g(grow, print, n // 10)

def shrink(n):
    f_then_g(print, shrink, n // 10)

def inverse_cascade(n):
    grow(n)
    print(n)
    shrink(n)

inverse_cascade(123)
```

输出：

```text
1
12
123
12
1
```

| 部分 | 执行安排 | 输出 |
|---|---|---|
| `grow(123)` | 先递归，再打印 | `1`、`12` |
| `print(123)` | 打印完整数字 | `123` |
| `shrink(123)` | 先打印，再递归 | `12`、`1` |

`f_then_g` 接收函数本身，例如 `grow`；其中的 `f(n)` 才发起调用。先完整执行 `f(n)`，再执行 `g(n)`。本题整数 `n` 为零时，`if n` 不成立，两个调用都跳过。

### 参数与打印时机必须分开看

```text
grow(123)
  → f_then_g(grow, print, 12)
  → 先 grow(12)，后 print(12)

grow(12)
  → f_then_g(grow, print, 1)
  → 先 grow(1)，后 print(1)

grow(1)
  → f_then_g(grow, print, 0)
  → 不打印，返回
```

返回时先打印 `1`，再打印 `12`。`grow(123)` 本身不会打印 `123`，因为交给辅助函数之前已经做了 `// 10`。

- `123 // 10 == 12`：去掉最后一位。
- `123 % 10 == 3`：只取最后一位。
- 增长和缩短两侧的递归参数都变小；输出方向由打印的位置决定。

## 4. Tree Recursion：多个分支与返回值

一次调用执行多个递归调用，产生树形计算过程。Fibonacci 的代码根据讲稿还原，输入为非负整数：

```python
def fib(n):
    if n == 0:
        return 0
    if n == 1:
        return 1
    return fib(n - 2) + fib(n - 1)

print(fib(4))  # 3
```

Python 先完整计算加号左侧，再计算右侧，最后相加返回：

```text
fib(4) → 3
├── fib(2) → 1
│   ├── fib(0) → 0
│   └── fib(1) → 1
└── fib(3) → 2
    ├── fib(1) → 1
    └── fib(2) → 1
        ├── fib(0) → 0
        └── fib(1) → 1
```

相同参数的 `fib(2)` 出现两次。这份实现没有保存并复用结果，每次调用都重算。不是所有树递归都慢；这里主要慢在大量重复计算。讲稿的 `@trace` 是观察调用与返回的工具，不是递归本身必需的部分。

### 个人重点：内层的左右分支，只完成外层的一次赋值

以下是学习中的补充练习：

```python
def ways(n):
    if n <= 1:
        return 1
    left = ways(n - 1)
    right = ways(n - 2)
    return left + right

print(ways(3))
```

不要省略中间的右分支，按执行位置跟踪：

1. 外层 `ways(3)` 执行 `left = ways(2)`，等待；外层 `left` 尚未赋值。
2. 内层 `ways(2)` 执行自己的 `left = ways(1)`；`ways(1)` 返回 `1`，内层 `left = 1`。
3. 内层继续执行自己的 `right = ways(0)`；`ways(0)` 返回 `1`，内层 `right = 1`。
4. 内层执行自己的 `return left + right`，返回 `2`。
5. 回到外层，刚才等待的赋值完成：外层 `left = 2`，外层 `n` 仍是 `3`。
6. 外层现在才执行自己的 `right = ways(1)`，得到 `right = 1`。
7. 外层执行自己的 `return left + right`，返回 `3`。

| 调用 | 自己的 n | 自己的 left | 自己的 right | 返回值 |
|---|---:|---:|---:|---:|
| 内层 `ways(2)` | 2 | 1 | 1 | 2 |
| 外层 `ways(3)` | 3 | 2 | 1 | 3 |

外层接收的是内层最终返回值，不是内层的同名变量。最后读取 `left` 时，使用保存的数字，不会再次调用函数。

## 5. Counting Partitions：整数分拆计数

`count_partitions(n, m)`：用不超过 `m` 的正整数凑出 `n`，共有多少种不同方案。

- `n` 是待凑的总数。
- `m` 是每个数的大小上限，不是使用次数。
- 每个数允许重复使用。
- 加数换顺序不算新方案；用非递减顺序统一书写。

例如 `count_partitions(5, 2)` 的全部方案：

```text
1 + 1 + 1 + 1 + 1
1 + 1 + 1 + 2
1 + 2 + 2
```

共三种。

### 两类互不重叠且覆盖全部方案

| 选择 | 剩余总数 | 允许上限 | 子问题 |
|---|---|---|---|
| 至少使用一个 m：先选走一个 m | `n - m` | 仍为 m，允许再用 | `count_partitions(n - m, m)` |
| 完全不用 m：没有选走任何数 | 仍为 n | 降到 `m - 1` | `count_partitions(n, m - 1)` |

拿 `1 + 2 + 2` 举例，拿走一个 `2` 后剩下的具体方案是 `1 + 2`，剩余总和为 `3`。上限仍须允许 `2`，否则会漏掉原方案。

### 完整代码

根据讲稿还原：

```python
def count_partitions(n, m):
    if n == 0:
        return 1
    if n < 0:
        return 0
    if m <= 0:
        return 0

    with_m = count_partitions(n - m, m)
    without_m = count_partitions(n, m - 1)
    return with_m + without_m

print(count_partitions(5, 3))  # 5
```

- `n == 0` 返回 `1`：恰好凑齐，剩下什么都不选是一种完成方式。
- `n < 0` 返回 `0`：选多了，没有合法方案。
- 仍未凑齐且 `m <= 0` 返回 `0`：无正整数可用。

基本情况的顺序有意义：`n == 0` 优先判断。讲稿转写的 non-positive 应按上下文理解为负数，不能把成功的零也列为失败。

讲稿示例：

```text
count_partitions(5, 3)
= count_partitions(2, 3) + count_partitions(5, 2)
= 2 + 3
= 5
```

前一类对应 `1 + 1 + 3`、`2 + 3`；后一类对应三个不含 `3` 的方案。

## 6. 我的主要易错点

| 曾经的混淆 | 正确解释 |
|---|---|
| 进入调用，参数就会打印 | 只有执行到 `print` 才打印 |
| 到基本情况就跳过剩余代码 | 只有 `return` 会立即结束；分支外的语句可能仍须执行 |
| 基本情况也继续套递归公式 | 基本情况已返回，后面的公式不执行 |
| 内层返回后，外层从头重算 | 从暂停的调用位置继续 |
| 各层共用同一个 n、left、previous | 每次调用有自己的参数和局部变量 |
| 内层返回 6，外层 n 就变成 6 | `left = f(...)` 把 6 赋给 left，n 不变 |
| 内层算完 left 就能返回 | 还要完成内层的 right 和最终 return |
| 外层 left 接收内层 left | 接收的是整个内层调用最终返回的值 |
| 最后用 left 时要重新算函数 | 读取已有变量不发起新调用 |
| 算过同一参数就自动复用 | 这份代码无缓存，新调用仍重算 |
| 分拆的 m 是可用次数 | m 是每个部分的大小上限 |
| 用一个 m 后上限也减一 | 至少一个允许重复，上限不变 |
| 不用 m 时剩余总数也减少 | 没选走任何数，总数 n 不变 |

计算错误、漏写与转写应同概念问题区分。回答有歧义时，先确认是在说参数、返回值还是输出。

### 题 4：分拆分类

对 `count_partitions(6, 3)`，写出两个子问题，并列出“至少一个 3”的全部方案。解释为什么不用把方案的不同排列分别计数。

### 答案

1. 输出依次为 `base`、`end 0`、`back 1`、`end 1`，各占一行。增加 `return` 后消失的是 `end 0`；外层仍继续。

3. `score(2)` 返回 `2 + 2 + 1 = 5`。最外层 n = 3，left = 5，right = 2，返回并打印 8。内层返回 5，赋给外层 left，不改变外层 n。
4. 子问题为 `(3, 3)` 和 `(6, 2)`。至少一个 3 的方案为 `1 + 1 + 1 + 3`、`1 + 2 + 3`、`3 + 3`。分拆只看各部分的组成，排列不产生新方案。
