## 1. 函数返回函数与父环境

### 1.1 `print`、`return`、函数调用是三件事

```python
def print_all(x):
    print(x)
    return print_all

print_all(1)(3)(5)
```

这段代码依次打印 `1、3、5`，整个表达式的最终值是 `print_all` 函数。

| 写法 | 意思 |
|---|---|
| `print(x)` | 显示 `x`；不会替外层函数返回 `x` |
| `return x` | 把 `x` 对应的值交回调用处 |
| `return print_all` | 返回函数本身，不调用它 |
| `return print_all(x)` | 先调用 `print_all(x)`，再返回这次调用的结果 |

`print_all(1)` 返回一个函数，因此后面的 `(3)` 可以调用这个返回值。每次调用结束后，是否继续调用由外面的表达式决定。

**曾经卡住的问题：是不是 `return` 后尽量不要加括号，才能避免无限递归？**

不是。要根据目的选择：返回函数本身，不加调用括号；调用函数并返回结果，加括号。是否无限递归取决于调用过程能否终止，不取决于 `return` 后有没有括号。

### 1.2 每次调用都有独立的 frame

```python
def print_sums(x):
    print(x)

    def next_sum(y):
        return print_sums(x + y)

    return next_sum


a = print_sums(1)
b = a(3)
a(5)
b(5)
```

输出是：

```text
1
4
6
9
```

两个关键规则：

- **调用函数时**，创建新的调用 frame，保存这次调用的参数和局部名字。
- **定义函数时**，函数关联它的定义环境。以后调用它时，新调用 frame 的 parent 由这个定义环境决定。

执行前两行后：

```text
a → 第一个 next_sum 函数 → 父 frame 中 x = 1
b → 第二个 next_sum 函数 → 父 frame 中 x = 4
```

两个函数虽然都叫 `next_sum`，但它们是不同的函数对象，关联不同的父 frame。

“绑定”就是名字对应某个值。值可以是数字，也可以是函数。`a`、`b` 绑定的是函数；父 frame 中的 `x` 绑定的是数字。

### 1.3 为什么打印 4，不代表 b 等于 4？

执行 `b = a(3)` 时：

```text
a(3)
  → 在 a 的父 frame 找到 x = 1，当前 y = 3
  → 调用 print_sums(4)
  → 新建 frame，其中 x = 4
  → 打印 4
  → 创建并返回新的 next_sum 函数
  → b 绑定到这个新函数
```

**4 是传入 `print_sums` 的参数，也是被打印的数字；返回值却是新函数。** 返回什么要看 `return`，不能只看参数或打印结果。

外层调用返回后，内部函数仍然关联它的父环境，因此那个环境中的 `x` 仍可被访问。这体现了闭包：函数保留对其定义环境的访问。

### 1.4 调用和重新赋值不同

```python
a = print_sums(3)  # a 的父环境中 x = 3
b = a(2)          # b 的父环境中 x = 5
a = a(4)          # 先用旧 a 计算，再把返回的新函数赋给 a
b(1)              # 打印 6
a(1)              # 打印 8
```

第三行之后，`a` 关联 `x = 7` 的 frame，`b` 仍关联 `x = 5` 的 frame。

- `a(4)`：调用 a，不会单凭这次调用就重新绑定 a。
- `a = a(4)`：把调用的返回值重新赋给 a，改变 a 的绑定。

在这些例子中，创建新的 `x` 不会改掉旧 frame 的 `x`。函数也不会自动转向最新创建的 frame。

## 2. 递归的环境图与逐层返回

### 2.1 阶乘：先调用，再完成等待的乘法

下面所有阶乘例子都假设输入是非负整数。

```python
def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)


result = fact(3)
```

向下调用时：

| frame | 参数 | 等待完成的计算 |
|---|---|---|
| f1 | n = 3 | 3 × fact(2) |
| f2 | n = 2 | 2 × fact(1) |
| f3 | n = 1 | 1 × fact(0) |
| f4 | n = 0 | 直接返回 1 |

这里不是同一个 `n` 不断被改写。四个 frame 分别保存自己的 `n`。

向上返回时：

```text
fact(0) → 1
fact(1) → 1 × 1 = 1
fact(2) → 2 × 1 = 2
fact(3) → 3 × 2 = 6
```

最外层最终得到一个结果 `6`，不是一组中间值。没有 `print` 就不会主动打印这些结果。

### 2.2 必须区分两种关系

| 关系 | 回答的问题 |
|---|---|
| 调用与返回关系 | 这次调用完成后，把结果交回哪里？ |
| parent 环境关系 | 当前 frame 找不到名字时，去哪里找？ |

**`fact(3)` 调用了 `fact(2)`，不代表后者的 parent 是前者的 frame。**

`fact` 定义在 global frame，因此这些调用 frame 的 parent 都是 global frame。返回时则回到发起调用的位置，继续完成计算。

### 2.3 终止条件必须能到达

```python
def countdown(n):
    if n == 0:
        return
    print(n)
    return countdown(n - 1)
```

从正整数开始，每次减 1，最终到达 0。若删除基本情况，就会持续递归，最终触发 Python 的 `RecursionError`。从负数开始不断减 1，也到不了 0。

因此不能只检查“有没有 if”，还要检查：**递归是否不断接近能终止的情况。**

## 3. 验证递归正确性：Recursive Leap of Faith

上一节追踪执行；这一节学习验证逻辑。

“递归的信任跳跃”是：**假设更小问题的调用能正确完成，再检查当前层能否用它得到正确答案。** 不是凭空相信整个函数正确。

```python
def sum_to(n):
    if n == 0:
        return 0
    return n + sum_to(n - 1)
```

假设输入是非负整数，按三步检查：

1. **基本情况正确**：`sum_to(0)` 返回 0，符合定义。
2. **递归步骤正确**：假设 `sum_to(n - 1)` 返回 `1 + 2 + … + (n - 1)`，加上 n 后就是目标结果。
3. **能到达基本情况**：每次 n 减 1，最终到达 0。

例如验证 `sum_to(4)`，可以把 `sum_to(3)` 当作已经正确返回 6 的功能，再检查 `4 + 6 = 10`，不用每次展开所有 frame。

这与数学归纳法相联系。画 frame 帮助理解执行，使用更小问题的正确性帮助理解为什么算法成立。

## 4. 相互递归：Luhn 算法

### 4.1 先分清算法规则

从最右边开始，交替进行：

```text
保持 → 加倍 → 保持 → 加倍 → …
```

加倍结果超过 9，就把结果的两位相加。注意：加倍是 **乘以 2**，不是加 2。

例如 `563`：

| 数字（从右往左） | 处理 | 贡献 |
|---|---|---:|
| 3 | 保持 | 3 |
| 6 | 6 × 2 = 12，再算 1 + 2 | 3 |
| 5 | 保持 | 5 |

总和是 `3 + 3 + 5 = 11`。Luhn 和是 10 的倍数时，通过这项校验；这不意味着卡片真实存在或可用。

### 4.2 三个函数各自负责什么

| 函数 | 职责 |
|---|---|
| `double_digit(d)` | 只处理一位数字：加倍，必要时把两位相加 |
| `luhn_sum(n)` | 当前最右位保持，剩余部分交给 double 版本 |
| `luhn_sum_double(n)` | 当前最右位加倍处理，剩余部分交给保持版本 |

辅助函数处理当前位；另一个 Luhn 函数处理剩余部分。不要把这两次调用混在一起。

### 4.3 完整实现

输入假设为非负整数。

```python
def double_digit(d):
    doubled = d * 2
    if doubled > 9:
        return doubled // 10 + doubled % 10
    return doubled


def luhn_sum(n):
    if n < 10:
        return n

    last = n % 10
    rest = n // 10
    other_result = luhn_sum_double(rest)
    return last + other_result


def luhn_sum_double(n):
    last = n % 10
    rest = n // 10
    transformed = double_digit(last)

    if n < 10:
        return transformed

    other_result = luhn_sum(rest)
    return transformed + other_result
```

拆数字的操作：

```python
563 % 10   # 3：最右一位
563 // 10  # 56：左边剩余的整个数字，不是只取相邻的一位
```

### 4.4 `return` 如何把计算接起来

```python
return last + luhn_sum_double(rest)
```

可以拆成：

```python
other_result = luhn_sum_double(rest)
total = last + other_result
return total
```

**调用表达式把任务交出去；返回值把算好的数字带回来；当前层再组合结果。** `other_result` 是接收返回数字的变量，不是被调用的函数。

### 4.5 完整追踪 `luhn_sum(563)`

```text
luhn_sum(563)
  last = 3，rest = 56
  保存 3，等待 luhn_sum_double(56)

luhn_sum_double(56)
  last = 6，rest = 5
  transformed = double_digit(6) = 3
  保存处理后的 3，等待 luhn_sum(5)

luhn_sum(5)
  只有一位，返回 5

回到 luhn_sum_double(56)
  other_result = 5
  返回 3 + 5 = 8

回到 luhn_sum(563)
  other_result = 8
  返回 3 + 8 = 11
```

**为什么不能把 8 当作最终答案？** 因为 8 只包括剩余部分 56 的贡献，最外层保存的 3 还没有加进去。

### 4.6 为什么交替调用，为什么会停止

- 保持版本调用加倍版本，是为了让下一位加倍。
- 加倍版本调用保持版本，是为了让下一位不加倍。
- 如果加倍版本继续调用自己，就会连续两位都加倍，破坏交替规则。

结束条件的寻找方法：**什么时候当前函数可以独立给出答案，不用继续递归？**

只剩一位，即 `n < 10` 时：

- 保持版本返回 n。
- 加倍版本返回 `double_digit(n)`。

停止拆分，不代表可以跳过这一位该做的加倍处理。每次递归传入 `n // 10`，数字变短，最终到达基本情况。算法不需要预先规定数字位数，但实际 Python 递归深度有限。

## 5. 递归与循环的转换：识别状态

本节换成普通的各位数字求和，**没有 Luhn 的交替加倍规则**。例如 `563` 的普通数字和是 14，Luhn 和是 11。

### 5.1 普通递归：返回时再加

```python
def sum_digits(n):
    if n < 10:
        return n
    return n % 10 + sum_digits(n // 10)
```

每层等待剩余部分的结果，返回时再加上当前位。

### 5.2 循环：在同一个 frame 更新状态

```python
def sum_digits_iter(n):
    digit_sum = 0
    while n > 0:
        last = n % 10
        n = n // 10
        digit_sum = digit_sum + last
    return digit_sum
```

需要跨轮次保存的状态是：

- n：尚未处理的数字。
- digit_sum：已经处理的各位之和。

`last` 是每轮临时取出的位，下一轮会重新计算。

以 426 为例：

```text
(n, digit_sum)
(426, 0) → (42, 6) → (4, 8) → (0, 12)
```

循环每轮不会创建新的函数调用 frame，而是在原调用 frame 中更新绑定。

**曾经的问题：没有加倍，是不是循环不够灵活？**

不是。这里没有加倍，是因为换了任务。循环也能实现 Luhn，只需额外记录“当前位是否应该加倍”。相互递归通过选择哪个函数来表示这种状态，循环可以通过变量表示。

### 5.3 把循环状态变成递归参数

```python
def sum_digits_rec(n, digit_sum):
    if n == 0:
        return digit_sum

    last = n % 10
    rest = n // 10
    return sum_digits_rec(rest, digit_sum + last)


result = sum_digits_rec(426, 0)
```

调用过程：

```text
sum_digits_rec(426, 0)
  → sum_digits_rec(42, 6)
    → sum_digits_rec(4, 8)
      → sum_digits_rec(0, 12)
        返回 12
```

关键转换：**循环中的状态更新，变成下一次递归调用的参数。**

每次传给下一层的是两个参数，不是返回两个值。最后只返回累计和 12。

### 5.4 加法发生在什么时候？

```python
return sum_digits_rec(rest, digit_sum + last)
```

先计算参数里的 `digit_sum + last`，然后调用下一层。因此累计发生在向下调用时，最深层已经拿到完整答案。返回过程中只把同一个答案逐层返回，不再加一次。

这里也没有修改旧 frame 中的 `digit_sum`；新累计和作为参数绑定在新 frame 中。

| 写法 | 在哪里累计 | 如何保存进度 |
|---|---|---|
| 普通 `sum_digits` 递归 | 内层返回后做加法 | 各调用保存等待完成的计算 |
| `sum_digits_iter` 循环 | 每轮立刻加入累计和 | 同一个 frame 更新变量 |
| 带累计参数的 `sum_digits_rec` | 下一次调用前计算新累计和 | 新 frame 接收新参数 |

将循环写成这种递归形式，不代表 Python 会把它自动变成循环；它仍会创建递归调用，并受到递归深度限制。

## 6. 本次学习最值得反复检查的区别

| 容易混淆的点 | 正确区分 |
|---|---|
| 打印了 4，所以返回 4 | 打印值与返回值分别看 `print` 和 `return` |
| 参数算出 4，所以函数返回 4 | 参数传进去后，返回什么由函数体决定 |
| 同名函数对应同一个 frame | 同一函数每次调用都创建新 frame |
| 最新算出的 x 会替换旧 x | 本例中各 frame 的 x 独立保存 |
| b 在 global，所以 x 也在 global | b 绑定函数，函数可以关联含有 x 的局部父环境 |
| 谁调用我，谁就是 parent | 调用关系与定义环境决定的 parent 关系不同 |
| 有 if 就保证递归停止 | 还必须让递归能到达基本情况 |
| 当前位贡献等于剩余部分结果 | 当前层分别保存两者，再按规则组合 |
| 进入新调用意味着旧调用结束 | 旧调用通常暂停等待结果，随后继续执行 |
| 累计参数在返回时变化 | 新累计参数在向下调用前计算，绑定到新 frame |
